# check-workflow-discipline.py rule R4: pull-request workflows that run with no
# paths / paths-ignore filter, each with its reason after the `#`.
# A file named here must exist; remove its line when it gains a filter.
acl-assertions.yml      # always reports a check; its jobs start the Rust build only when the ACL declaration, evaluator or Cargo inputs change
agent-references.yml    # an assistant session link can land in any file, most often a doc; scans only the changed files
codeql.yml              # every pull request carries a code-scanning result; a run that does not start leaves the commit unanalyzed. About three minutes, not a required check
ci.yml                  # the public build and the always-on guards; its `changes` job decides which jobs need to run
contributor-trust.yml   # required check on main (ADR 1221): decides from the author and paths whether a security review is needed
leak-gate.yml           # required check on main: a deployment name or key can be added in any file
slot-wal-cap.yml        # the slot WAL cap check reads every tracked file, so a size beside the setting can land in any path; it takes a second
stable-guard.yml        # filtered by branch instead: runs only for pull requests into `stable`, which it closes (ADR 1231)
upstream-pins.yml       # a pinned upstream version can sit in any file type (Cargo, lock, Dockerfile, role default, Go, HTML); the check is a sub-minute Python scan
commit-identity.yml     # sets the commit-identity status on every pull request (ADR 1276): reads commit metadata from the API, under a minute
