# Ansible — goat Deployment

Automates all infrastructure and service deployment. Terraform creates the resources, Ansible configures them.

## Architecture

```
Terraform (VPSes, DNS, security groups, S3)
    ↓
inventory/generate.sh (reads TF outputs, fetches SSH keys, discovers bridge mesh IPs)
    ↓
Ansible playbooks (SSM → relay VPSes, mesh SSH → bridges/network host)
```

### Connectivity

- **Relay VPSes** — AWS SSM Session Manager (no SSH). Requires S3 bucket for file transfer (`ansible_aws_ssm_bucket_name` in inventory).
- **Bridge VPSes** — SSH over Netbird mesh IP. Bridges are mesh peers.
- **Network host** — SSH over Netbird mesh IP (`100.127.1.23`).
- **TAK server** — SSH over Netbird mesh IP (when hardware is enrolled).

## Quick Start

```
brew install ansible
cd ops/ansible

# Generate inventory from Terraform
inventory/generate.sh

# Deploy by tier
ansible-playbook site-infra.yml -e shared_turn_secret=... -e nb_relay_auth_secret=...
ansible-playbook site-services.yml
ansible-playbook bridge.yml -e netbird_setup_key=$NETBIRD_SETUP_KEY
ansible-playbook tak-server.yml

# Or deploy everything
ansible-playbook site.yml
```

## Deployment Tiers

`site.yml` runs all tiers in dependency order. Each tier has its own playbook for independent use.

| Tier | Playbook | What it covers |
|---|---|---|
| 1. Infrastructure | `site-infra.yml` | VPS relays, network host firewall, mesh DNS, network host relay clients |
| 2. Services | `site-services.yml` | Caddy hosting, status page, smoketest, secwatch, airdefenders |
| 3. Bridge | `bridge.yml` | Bridge VPSes for partner connectivity (requires `-e netbird_setup_key`) |
| 4. TAK | `tak-server.yml` | TAK Server (requires hardware + Docker image from tak.gov) |

Tiers 3 and 4 skip cleanly if their inventory groups are empty.

## Playbooks

### VPS Relays

| Playbook | Target | What it does |
|---|---|---|
| `relay-server.yml` | `relay_servers` | Installs rathole, Coturn (hardened), Netbird relay container, dnsmasq. Stores credentials in Secrets Manager. |
| `relay-client.yml` | `router` | Installs rathole client on the router. |

### Network Host Infrastructure

| Playbook | Target | What it does |
|---|---|---|
| `nethost-firewall.yml` | `nethost` | UFW host firewall — mesh-only SSH, service ports. |
| `nethost-dns.yml` | `nethost` | Deploys CoreDNS (`coredns/coredns:1.11.3`) + mesh-hosts zone file, updates Netbird nameserver group via API. |
| `nethost-relay.yml` | `nethost` | Fetches relay credentials from Secrets Manager, writes per-relay rathole client configs, registers STUN/relay servers. |
| `nethost-strip-headers.yml` | `nethost` | Strips server identification headers from Netbird management services. |

### Network Host Services

| Playbook | Target | What it does |
|---|---|---|
| `nethost-serve.yml` | `nethost` | Caddy reverse proxy for static apps. Config generated from `ops/serve/services.yaml` via `generate.py`. |
| `nethost-status.yml` | `nethost` | Status page (`isitup.netbird.legacy.example`) — health checks every 5 min, 30-day history. |
| `nethost-smoketest.yml` | `nethost` | Smoketest dashboard — automated service validation. |
| `nethost-secwatch.yml` | `nethost` | Security scanner deployment. |

### Bridge + TAK

| Playbook | Target | What it does |
|---|---|---|

### Orchestrators

| Playbook | What it runs |
|---|---|
| `site.yml` | All tiers in order (infra → services → bridge → TAK) |
| `site-infra.yml` | Tier 1: `relay-server` → `nethost-firewall` → `nethost-dns` → `nethost-relay` |
| `site-services.yml` | Tier 2: `nethost-serve` → `nethost-status` → `nethost-smoketest` → `nethost-secwatch` → `airdefenders` |

## Inventory

Generated by `inventory/generate.sh` from Terraform outputs. Four host groups:

| Group | Connection | Source |
|---|---|---|
| `relay_servers` | SSM (`community.aws.aws_ssm`) | `terraform output relays` |
| `bridge_servers` | SSH via mesh IP | `terraform output bridges` + SSM mesh IP discovery |
| `nethost` | SSH via mesh IP (`100.127.1.23`) | Static |
| `tak_servers` | SSH via mesh IP | Manual (when hardware enrolled) |

Relay inventory includes `aws_region`, `rathole_secret_name`, `ansible_aws_ssm_bucket_name`, and `ansible_remote_tmp`.


## Extra Variables

| Variable | Used by | Description |
|---|---|---|
| `shared_turn_secret` | `relay-server.yml` | Shared Coturn auth secret. Reads existing or generates new if unset. |
| `nb_relay_auth_secret` | `relay-server.yml`, `nethost-relay.yml` | Netbird relay auth secret (from network host `config.yaml`). |
| `netbird_setup_key` | `bridge.yml` | Netbird enrollment key. Required on first bridge deploy. |

## Targeting Specific Hosts

```
ansible-playbook relay-server.yml --limit relay-rla
ansible-playbook bridge.yml --limit bridge-rla
ansible-playbook site.yml --limit relay-rlb,nethost
```

## Azure DNS-01 for the mgmt host's public TLS (`traefik-acme.yml`)

`traefik-acme.yml` issues the mgmt host's Let's Encrypt certificate by DNS-01 through
Cloudflare (default) or Azure DNS. A site picks Azure in its target group's group_vars;
unset, the play and its render are the Cloudflare path. Azure uses Traefik's lego
`azuredns` provider with an Entra service principal (client secret), so it works on hosts
with no managed identity, such as on-premises machines. The secret reaches the host only
through `/opt/mgmt-host/.env` (0600), never a rendered file or a command line.

| Variable | Default | Meaning |
|---|---|---|
| `traefik_acme_dns_provider` | `cloudflare` | `azure` selects Azure DNS |
| `traefik_acme_azure_tenant_id` | required | Entra tenant of the service principal |
| `traefik_acme_azure_client_id` | required | Application (client) ID |
| `traefik_acme_azure_client_secret` | required | Secret: declare as `"{{ lookup('env', 'AZURE_DNS_CLIENT_SECRET_<SITE>') }}"` |
| `traefik_acme_azure_subscription_id` | required | Subscription holding the zone |
| `traefik_acme_azure_resource_group` | required | Resource group holding the zone |
| `traefik_acme_azure_zone_name` | lego finds it by SOA | Pins the zone; every requested name must sit in it |
| `traefik_acme_azure_environment` | `public` | `usgovernment` or `china` for those clouds |
| `traefik_acme_dns_resolvers` | `1.1.1.1:53,8.8.8.8:53` | Propagation-check resolvers, either provider |

The pre-flight names any empty Azure value and refuses before touching the host.
`goat-standup.sh` phase 7 (and `goatbuilder standup`) then needs
`AZURE_DNS_CLIENT_SECRET_<SITE>` set instead of `CLOUDFLARE_API_TOKEN_<SITE>`; with
`posture.py init`, `AZURE` names are left for an outside value, never generated.

**Admin step, once per zone:** an Entra app registration with a client secret, and the
DNS Zone Contributor role for its service principal scoped to the DNS zone (not the
resource group or subscription).

**Status:** rendered and pre-flight tested offline; not yet run against a real Azure DNS zone.

## SSM Prerequisites

The SSM connection plugin requires:
- S3 bucket for file transfer (created by Terraform, name in inventory)
- `OBJC_DISABLE_INITIALIZE_FORK_SAFETY=YES` on macOS (set in `.envrc`)
- `ansible_remote_tmp=/tmp/.ansible/tmp` for relay hosts (SSM runs as `ssm-user`)

    └── tak-federation.xml.j2            # TAK federation config
