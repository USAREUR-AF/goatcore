# GB-437: the bootstrap NetBird identity needs a rotation, which a standup never does

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-437` is printed by `goatbuilder`. The same text offline: `goat explain GB-437` or `goatbuilder explain GB-437`.

## What it means

The bootstrap service user already holds a token, and the store holds no copy of it that authenticates as that user; or the store holds a value that is neither a working token nor this standup's pending one; or a rotation was started and not finished (two token rows). A standup never replaces a stored token or makes a second one (ADR 1274), so it stops here. Nothing was changed.

## Why it happens

- the stored token expired or was revoked in the dashboard
- the stored copy was lost, or the service user was made by hand
- a rotation stopped after its install, before the old row was removed

## What to do

One line per step or alternative:

```text
renew or recover the token with the rotation ADR 1274 describes (run by a person, never by the standup)
for an unfinished rotation: once the token's consumers have the new value, run the bootstrap-token-revoke command the message names
```
