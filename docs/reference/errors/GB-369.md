# GB-369: a phase's command reads an environment variable that is not set

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-369` is printed by `goatbuilder`. The same text offline: `goat explain GB-369` or `goatbuilder explain GB-369`.

## What it means

A phase's command expands $NAME or ${NAME}, and nothing set NAME in the environment goatbuilder runs it in. Phases run under bash -u, so the command would stop with 'NAME: unbound variable' before its program starts, partway through the node. join-node checks every phase it will run before the first one and refuses, naming the phase and each variable; a phase that stopped this way prints bash's line, which this code names.

## Why it happens

- the variable is kept under the secrets posture, which loads it for the commands it wraps, not for the shell that expands the phase's command (a founder's OWNER_EMAIL, the bootstrap administrator's address)
- the variable was exported in another shell, or before a restart

## What to do

One line per step or alternative:

```text
export NAME=<value>, then re-run with the same --from
ops/scripts/with-secrets goatbuilder <the same command> (when the store keeps NAME)
```
