# GB-336: --over-ssh's host flags are given where they do not belong

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-336` is printed by `goatbuilder`. The same text offline: `goat explain GB-336` or `goatbuilder explain GB-336`.

## What it means

--over-ssh and its host flags belong to `goatbuilder federate init`, which measures our half of phase 3 on the edge and core hosts over SSH. Given to `goatbuilder federate plan`, or to a peering run (`goatbuilder federate <partner>`), they would be ignored, so the command refuses. A peering run measures phase 3 over SSH by itself, with FED_MEASURE=ssh (the default). Nothing ran.

## Why it happens

- the flags were given to `federate plan` or to a peering run, which read the deployment's own declarations
- the flags were meant for init, and were typed before the word init

## What to do

One line per step or alternative:

```text
goatbuilder federate init --over-ssh <partner> --side edge --half-out <file> (init first, then its flags)
drop the flags from a peering run or a plan
```
