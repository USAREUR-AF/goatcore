# GB-298: an IPsec rotation under way, or not yet retired, is not the one asked for

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-298` is printed by `goatbuilder`. The same text offline: `goat explain GB-298` or `goatbuilder explain GB-298`.

## What it means

goatbuilder federate rotate &lt;partner> ipsec-leaf|ipsec-ca records the rotation it starts in &lt;work>/.rotation-ipsec (its id, its kind and, for ipsec-ca, the partner's attestation: the fingerprint it read back of our new CA) before phase 11 runs, and removes the record once phase 11 passed. Each rotation is also kept in &lt;work>/ipsec-rotations.json, with when it switched, passed phase 14 and was retired. A run that finds a record resumes that rotation with the same id, so goat-peering-edge sets nothing aside twice. This run was refused before anything ran: it asked for another kind or another read-back than the record names (fingerprints are compared in one form, sha256: and lowercase), the record is empty or not a rotation record, a retire was asked while a rotation is under way or of the other kind than the rotation retired, or a new rotation was asked while an earlier one switched and is not retired.

## Why it happens

- an earlier rotation stopped before phase 11 passed, and a rotation of the other kind was asked for
- the partner's read-back changed between the run that started the rotation and this one
- an earlier rotation switched and its retire step has not run
- the record was emptied or edited by hand

## What to do

One line per step or alternative:

```text
finish the rotation the record names with the command that started it (the message names its id and kind)
retire the earlier rotation once phase 14 passed on both sides: goatbuilder federate rotate <partner> ipsec-leaf|ipsec-ca --retire <id>
removing <work>/.rotation-ipsec starts a new rotation id; the edge keeps /etc/swanctl/.previous-<id>/ as it is (after a GB-302 rollback, with the old pair live), and nothing removes it yet
```
