# GB-359: federate allocate names a peering the config does not declare

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-359` is printed by `goatbuilder`. The same text offline: `goat explain GB-359` or `goatbuilder explain GB-359`.

## What it means

`goatbuilder federate allocate <peering>` allocates the ports, addresses and names of one declared peering. The peering named on the command line is not in the config's `peerings:`, and a peering nobody declared is one nobody reviewed (contract C1). Nothing was allocated or written. A peering run whose partner is not declared is GB-149.

## Why it happens

- the peering name was mistyped
- the peering is declared in another environment's config, or not yet declared at all

## What to do

One line per step or alternative:

```text
goatbuilder federate allocate (with no name, it allocates every declared peering)
declare the peering under `peerings:` in the config the message names, then run the same command again
```
