# GB-440: a core joined to the founder's own site, which declares no standby pair

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-440` is printed by `goatbuilder`. The same text offline: `goat explain GB-440` or `goatbuilder explain GB-440`.

## What it means

Standup builds a founder site's first core, so a core join-node adds to that site is a second one, and the only second core a site runs is its streaming standby (`intra_site_pair: true`). The site does not declare the pair, so site-bootstrap would skip the standby and the node would come up as a second primary: its own empty NetBird database, and a management service whose OIDC endpoint is a Hydra that runs only on the primary. The run is refused at its first phase (phase 1, or the phase a resume starts at) and phase 13's step is the same refusal, so nothing on the node is changed. A run that stops before phase 13 is not refused.

## Why it happens

- the founder's site is a goatlite, which declares no intra_site_pair
- the node was meant to be the first core of a new site, and was given the founder's site

## What to do

One line per step or alternative:

```text
declare intra_site_pair: true in group_vars/<site>_hosts/vars.yml, with the values ops/ansible/roles/postgres-streaming-replication/README.md lists, then resume with --from 1
or join the node as the first core of a new site: --site <new site>, which declares goatnet_founder: false and join_founder_site: <founder>
```
