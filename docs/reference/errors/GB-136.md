# GB-136: the core has no receive store matching what the edge grants

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-136` is printed by `goatbuilder`. The same text offline: `goat explain GB-136` or `goatbuilder explain GB-136`.

## What it means

the core router's storage_manager has no store whose key expression equals an ingress scope the edge admits (from/&lt;partner>/\*\* by the spec's rule, or the rendered goat_zenoh_edge_ingress_key_exprs). A store wider than the grant, such as from/\*\*, declares a subscriber the edge refuses, so data would cross and not be kept.

## Why it happens

- the core keeps only a historical from/\*\* store
- the core's per-partner store names a different partner or lane than the edge grants

## What to do

One line per step or alternative:

```text
add a store on the core whose key_expr equals each admitted scope (the goat-zenoh role renders one per partner); keep a historical from/** store beside it if its data is needed
```
