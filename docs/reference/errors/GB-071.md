# GB-071: a site's leaf certificate is not on this controller

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-071` is printed by `goatbuilder`. The same text offline: `goat explain GB-071` or `goatbuilder explain GB-071`.

## What it means

A play that installs a site's leaf (the zenoh router, the LAN mgmt identity, the dashboard pair, the names collector) found the cert or key nowhere it looks: the site manifest's out_dir (&lt;deploy.state_dir>/&lt;site>-leaves), then a copy staged in this checkout or the main checkout. It refuses before touching a host.

## Why it happens

- the leaf was never minted for this site, or was minted on another operator's machine
- the manifest's out_dir points somewhere this machine does not have
- GOAT_LEAF_DIR is set to a directory that does not hold it

## What to do

One line per step or alternative:

```text
mint it into the out_dir: ops/scripts/mint-site-certs.sh <site> --only <leaf> (idempotent; an existing leaf is skipped)
copy an existing pair into <deploy.state_dir>/<site>-leaves/ (key mode 0600), never into the repository
```
