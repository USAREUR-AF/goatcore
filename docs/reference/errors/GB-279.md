# GB-279: a peering edge does not have the host firewall baseline switched on

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-279` is printed by `goatbuilder`. The same text offline: `goat explain GB-279` or `goatbuilder explain GB-279`.

## What it means

The peering plays require the host firewall baseline (roles/goat-host-firewall) on an edge, so the edge is held to the ports its peering declares. Every play a peering standup runs on an edge (peering-prepare.yml in phase 2, peering-wg.yml or peering-edge.yml in phase 11, peering-zenoh-edge.yml in phase 12) checks goat_host_firewall_baseline first, and goat_host_firewall_baseline was not true for this edge. The play refused before changing anything on the host. The baseline itself is applied by phase 11's play once the setting is on. A core host keeps the baseline opt-in.

## Why it happens

- the edge's group_vars do not set goat_host_firewall_baseline, and the role's default is false
- goat_host_firewall_baseline is set to false for the edge's group or host

## What to do

One line per step or alternative:

```text
set goat_host_firewall_baseline: true and goat_host_firewall_management_sources in group_vars/<edge group>/host-firewall.yml (copy ops/ansible/group_vars/_examples/peering-host-firewall.example.yml)
goatbuilder federate plan <partner> (the edge's host firewall row renders the ruleset it will load)
run the peering again: phase 11's play applies the baseline
```
