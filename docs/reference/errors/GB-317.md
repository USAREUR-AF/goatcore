# GB-317: a carrier rotation was asked for on a peering that has no carrier

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-317` is printed by `goatbuilder`. The same text offline: `goat explain GB-317` or `goatbuilder explain GB-317`.

## What it means

`goatbuilder federate rotate <partner> carrier` rotates the keys of the carrier, the link between a peering's edge and its peering forwarder. This peering declares no forwarder, neither with forwarder: on the peering in goatbuilder.yaml nor as peering_wg_via_forwarder: true in its edge group's group_vars, so its edge has no carrier and there is no carrier key to rotate. It stopped before anything ran: no key was set aside and no rotation id was kept.

## Why it happens

- the peering's edge reaches the partner directly, with no peering forwarder
- the forwarder is declared in a group the run does not deploy to: the run reads --edge-group, else &lt;partner>_edge, then peering_edges and all

## What to do

One line per step or alternative:

```text
goatbuilder federate rotate <partner> leaves (the keys a peering with no forwarder has to rotate; the peering key is `transport`, once built)
a peering that is relayed: declare forwarder: on it in ops/goatbuilder/goatbuilder.yaml, run goatbuilder federate allocate, review and commit what it writes, then rotate again
```
