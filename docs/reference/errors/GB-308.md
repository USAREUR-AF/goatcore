# GB-308: the partner's package offered is older than the one we hold

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-308` is printed by `goatbuilder`. The same text offline: `goat explain GB-308` or `goatbuilder explain GB-308`.

## What it means

At phase 5, a package from the partner signed by the key already bound was offered as their new one (by the directory step at &lt;work>/theirs.incoming.json, or copied over &lt;work>/theirs.canonical.json by hand), and its `issued` date is before the one of the package we hold, or it has no readable `issued` date while the one we hold has (ADR 1229). `issued` is the only member that orders a party's packages, so an older one is a replay or a rollback. It is refused, even with --accept-partner-package and its own digest, so a replay is never asked about and approved by habit. Nothing was placed; a file from the directory step was set aside as theirs.incoming.json.refused-&lt;UTC time>.

## Why it happens

- a directory, or a copy on the hand-exchange path, served an older package the partner once signed
- the partner rolled back to an earlier package without publishing it again

## What to do

One line per step or alternative:

```text
ask the partner on the call which package is current; keep the one you hold until they say
a partner that rolls back on purpose publishes the package again with a later issued date, then: goatbuilder federate <partner> --from 5 --accept-partner-package <digest>
```
