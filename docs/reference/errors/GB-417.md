# GB-417: a joining node or its founder does not declare the replication phase 13 wires

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-417` is printed by `goatbuilder`. The same text offline: `goat explain GB-417` or `goatbuilder explain GB-417`.

## What it means

join-node phase 13 at a joining site seeds the core node from its founder, then wires Spock on both sides: the node's own bootstrap, and spock-mesh-wire.yml on the founder. Those plays run their Spock roles only on a host whose own variables declare participates_in_spock true, an inter_site_spock_topology other than none and, for the kratos and hydra databases, ory_spock_enabled true (on router_role A); on any other host they do nothing and report done, so the founder gets no Ory replication node for the node to subscribe to. A goatlite founder declares none of them. The NetBird management tables replicate only where `spock_mesh_databases` names the netbird database pulling the `netbird_mgmt` replication set, whose repset holds the curated table list (ADR 1084 D1); the seed copies exactly that list and both seed-current checks compare it, so a site without it would be seeded once and then drift. Before phase 13 changes anything, spock-join-replication-declared.yml reads those variables on the node and on the founder's A host, as Ansible evaluates them, and stops naming each host, each missing value and the group_vars it belongs in. Nothing was changed.

## Why it happens

- the founder began as a goatlite, which renders participates_in_spock false and no ory_spock_enabled
- the joining site's group_vars were copied from a founder that never replicated
- the run's inventory holds no host of the founder's group with router_role A
- a site declares no `spock_mesh_databases`, or its netbird entry pulls another set, or its `netbird_mgmt` repset holds other tables than the seed's

## What to do

One line per step or alternative:

```text
declare participates_in_spock: true, inter_site_spock_topology: explicit with inter_site_spock_peers naming the other site, and ory_spock_enabled: true in each named group_vars, then run join-node again with --from 13
declare spock_mesh_databases as ops/ansible/roles/spock-mesh-peering/defaults/main.yml shows for mgmt-layer replication: name netbird, replication_sets [netbird_mgmt], repset netbird_mgmt with tables "{{ spock_mesh_netbird_mgmt_tables }}"
```
