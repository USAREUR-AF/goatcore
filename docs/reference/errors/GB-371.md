# GB-371: the peering directory did not answer, or what answered is not a peering directory

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-371` is printed by `goatbuilder`. The same text offline: `goat explain GB-371` or `goatbuilder explain GB-371`.

## What it means

goatbuilder federate directory asked the directory for /v1/version (and, on a release older than saltlick v0.6.0, /healthz) and got no answer, or an answer that is not a saltlick directory.

## Why it happens

- the URL is wrong, or names a host that is not the directory
- the directory is down or restarting (a deploy replaces its instance, a few minutes)
- this machine has no route to the internet, or a proxy refuses the host

## What to do

One line per step or alternative:

```text
curl -sS <url>/healthz should print {"status":"ok"}
if you run the directory: its runbook says how to check the host and bring it back
```
