# GB-441: a site's Spock publisher host is also a peer's, so that peer would subscribe to itself

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-441` is printed by `goatbuilder`. The same text offline: `goat explain GB-441` or `goatbuilder explain GB-441`.

## What it means

Each peer subscribes to a site at that site's Spock publisher host, which is spock_mesh_publisher_host or, when it is unset, the host of the site's signal_uri. This site's host is also a peer's, so the peer's subscription would point at the peer itself. spock-mesh-peering stopped before it wired anything. The message names the host and the peer.

## Why it happens

- a joining site's signal_uri names its founder's enrolment name, and the site sets no spock_mesh_publisher_host
- spock_mesh_publisher_host was copied from another site's group_vars

## What to do

One line per step or alternative:

```text
set spock_mesh_publisher_host in group_vars/<site>_hosts/vars.yml to the address the other sites reach this site's Postgres at (its mesh IP, ADR 1084), then run the step again
```
