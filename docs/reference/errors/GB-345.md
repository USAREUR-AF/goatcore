# GB-345: there is nothing to seed again

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-345` is printed by `goatbuilder`. The same text offline: `goat explain GB-345` or `goatbuilder explain GB-345`.

## What it means

`goatbuilder join-node ... --reseed` copies a node's replicated tables again from its founder after the founder invalidated the slot it keeps for the node. Its first step (`spock-reseed.py lost`) read every slot the founder keeps for the node's subscriptions, and none reads `wal_status = lost`. A node whose slots are healthy catches up by itself; copying it again only costs the copy. Nothing was changed.

## Why it happens

- the node came back before the founder's slot for it passed `max_slot_wal_keep_size`
- the node or the site named is not the one whose slot was lost
- a later step ran before the lost step passed in this journal

## What to do

One line per step or alternative:

```text
read the slots on the founder: SELECT slot_name, active, wal_status FROM pg_replication_slots;
goatbuilder join-node <env> --site <site> --node <node> --class <class> --reseed --dry-run (it prints each step's command)
```
