# GB-374: a machine type or platform family file is not valid

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-374` is printed by `goatbuilder`. The same text offline: `goat explain GB-374` or `goatbuilder explain GB-374`.

## What it means

join-node and standup read what a machine converges as from ops/goatbuilder/targets/ and ops/goatbuilder/families/, and a private overlay's own files from ops/goatbuilder/overlay/. One of them is not readable, has an unknown field, names a value or a built-in step this goatbuilder does not have, runs a play its words do not limit to the type's group, or repeats a name. Or a host_vars or group_vars file that may declare a machine's platform_family is not readable YAML, or declares it as other than one word. The message names the file and why. Nothing ran.

## Why it happens

- a misspelt or unknown field in the file
- an overlay file with the name of a type or family the repository already has
- the file was written for another goatbuilder release: a main checkout newer than this goatbuilder release can change a file's format (goatbuilder --version names the release)
- a play's args set target more than once, to another group, or with -l
- a vars file with a YAML error, or platform_family as a list or mapping

## What to do

One line per step or alternative:

```text
correct the file the message names; ops/goatbuilder/targets/README.md is the format
when the checkout is newer than this release, build goatbuilder from it: cd crates && cargo build --release --locked -p goatbuilder
give an overlay's type a name of its own
```
