# GB-329: a file goatbuilder reads from the checkout is not well formed

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-329` is printed by `goatbuilder`. The same text offline: `goat explain GB-329` or `goatbuilder explain GB-329`.

## What it means

A verb read a file of the checkout (a pin table, the ladder, a record, a workflow, the intent schema), and what it holds does not parse as YAML or JSON, or the schema does not compile as JSON Schema draft 7. The file was read: this is not a permission or a missing file (GB-254). The message names the file and the parser's reason, with the line and column where the parser gives them.

## Why it happens

- a hand edit left the file malformed near the line named
- merge-conflict markers were left in the file
- the schema file comes from another commit than the rest of the checkout

## What to do

One line per step or alternative:

```text
git diff -- <the file the message names>
fix the line the message names, or restore the file: git checkout -- <the file>
goatbuilder pins --check
```
