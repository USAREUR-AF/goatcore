# GB-362: a site's own copy of a generic play does not say it was made from the current one

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-362` is printed by `goatbuilder`. The same text offline: `goat explain GB-362` or `goatbuilder explain GB-362`.

## What it means

A deployment may keep its own ops/ansible/&lt;site>-&lt;suffix> (for example &lt;site>-seed-from-peer.yml), which the drivers run in place of the generic site-&lt;suffix>. A copy names the version of the generic play it was made from in a first line `# derived-from: site-<suffix> sha256:<hex>`. This copy has no such line, or names a digest the current generic play no longer has, so the fixes the generic play gained since cannot be known to be in it. Nothing ran on the hosts; the run stopped before the site's play.

## Why it happens

- the copy predates the derived-from line
- the generic play changed after the copy was made (a fix, a new guard)
- the copy was edited from another checkout's generic play

## What to do

One line per step or alternative:

```text
compare the copy with the current ops/ansible/site-<suffix>, carry its changes in, and set the line to the digest the message prints
or make the site's file a wrapper that imports site-<suffix> with the site's own vars, which needs no line
or remove the copy, so the generic play runs
```
