# GB-339: two peerings on one forwarder declare different values for its machine

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-339` is printed by `goatbuilder`. The same text offline: `goat explain GB-339` or `goatbuilder explain GB-339`.

## What it means

A peering's forwarder: may declare the forwarder machine's own values: ansible_user (the user the forwarder play reaches it as), public_interface and ssh_sources. goatbuilder federate allocate renders them into the forwarder group's group_vars, which hold one value of each. Two peerings relayed by the same forwarder group declare different values for one of them, so allocate cannot tell which is the machine's. Nothing was written.

## Why it happens

- the value was changed on one peering's forwarder: and not on the other's
- two forwarders share one group (forwarder: group:), so their machines' values meet in one file

## What to do

One line per step or alternative:

```text
declare the same value on every peering of that forwarder, or on one of them only (the others take it)
give each forwarder machine its own group under forwarder: group:
```
