# GB-378: a machine type or platform family file is not goatcore's

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-378` is printed by `goatbuilder`. The same text offline: `goat explain GB-378` or `goatbuilder explain GB-378`.

## What it means

In an assembled tree (.goat-assembled at its root) the files in ops/goatbuilder/targets/ and ops/goatbuilder/families/ are held to the goatcore commit the marker names. One differs from that commit, is not in it, or cannot be compared with it. An overlay adds types and families, in ops/goatbuilder/overlay/, and replaces none. Nothing ran.

## Why it happens

- the overlay carries a file of a built-in type or family
- the overlay's own type is in ops/goatbuilder/targets/
- a file was edited in the assembled tree
- the tree's git does not have the goatcore commit, or the tree was assembled from local directories

## What to do

One line per step or alternative:

```text
move the overlay's own type or family to ops/goatbuilder/overlay/, under a name of its own, and re-assemble
re-assemble the tree from the overlay's pinned refs
a change to a built-in type is a change to goatcore
```
