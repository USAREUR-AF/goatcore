# GB-390: the rebuild cannot read what it would truncate

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-390` is printed by `goatbuilder`. The same text offline: `goat explain GB-390` or `goatbuilder explain GB-390`.

## What it means

The rebuild refuses before it changes anything when it cannot tell what the copy would lose. Either the node subscribes to a site that is not one of the sides given, so the slot that site keeps for the node is not read; or the node has no subscription from its founder, so there is nothing to copy through; or a table has no primary key, so the rows only the node holds cannot be told apart. Nothing was changed.

## Why it happens

- the node replicates with another joiner site that was not named with --peer
- the node's subscription from its founder was dropped by hand
- a table was added to a replication set without a primary key

## What to do

One line per step or alternative:

```text
name the other site: goatbuilder join-node <env> --site <site> --node <node> --class <class> --reseed --peer <other-site>
read the node's subscriptions: SELECT * FROM spock.sub_show_status();
```
