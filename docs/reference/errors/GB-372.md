# GB-372: the peering directory lacks a file a peering reads

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-372` is printed by `goatbuilder`. The same text offline: `goat explain GB-372` or `goatbuilder explain GB-372`.

## What it means

goatbuilder federate directory check (or show) found an item that is not there. Each missing item is one of two kinds, and the view names which. NOT HOSTED: the directory serves the route, and the party has not uploaded the file. ROUTE MISSING: the directory's release does not serve the route at all (a plain-text 404, or a route absent from its /v1/version list).

## Why it happens

- NOT HOSTED: the party has not run phase 5 of the peering, which uploads its entry, CA, SPIFFE bundle and its package for the counterparty
- NOT HOSTED: the party used another id, or uploaded to the single package slot instead of the one for this counterparty
- ROUTE MISSING: the directory runs a release older than the one that added the route (per-counterparty packages need saltlick v0.5.0)

## What to do

One line per step or alternative:

```text
NOT HOSTED: ask the party to run phase 5 (goatbuilder federate <peering> --from 5 --to 5), then check again
ROUTE MISSING: the directory's operator moves it to a release that serves the route; check which release runs with goatbuilder federate directory ls
```
