# GB-287: a joining site's leaf-cert manifest has no router leaf

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-287` is printed by `goatbuilder`. The same text offline: `goat explain GB-287` or `goatbuilder explain GB-287`.

## What it means

join-node deploys a joining site's data router (zenoh-deploy.yml), whose play reads the router leaf that mint-site-certs.sh mints from the site's manifest. The manifest names no leaf called router, so the plan was refused before any phase ran.

## Why it happens

- the manifest was written without the router entry ops/enrollment/manifests/TEMPLATE-certs.yaml carries

## What to do

One line per step or alternative:

```text
add a leaf named router to ops/enrollment/manifests/<site>-certs.yaml, as the template shows, with the site's own SANs
```
