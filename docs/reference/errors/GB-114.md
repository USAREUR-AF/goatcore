# GB-114: an edge half of phase 3 cannot be joined

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-114` is printed by `goatbuilder`. The same text offline: `goat explain GB-114` or `goatbuilder explain GB-114`.

## What it means

With two drivers, the edge driver measures phase 3's edge half with `goatbuilder federate init --over-ssh <partner> --side edge --half-out <file>` and prints its sha256 and a confirm code. The controller joins it with `--side core --edge-half <file> --edge-half-sha256 <code>` before it builds and signs the package. The half carries the edge's WireGuard public key, which the package is signed with, so it is joined only when it is the file the edge driver wrote. The file given could not be read; its sha256 is not the one confirmed; it is not an edge half; it was measured for another peering, on another host than this checkout's inventory names as the edge, or for another federation interface than the package asks for; or it was measured more than 24 hours ago, or later than now.

## Why it happens

- the file was changed or not copied whole on its way from the edge driver, or another file was given
- the confirm code was mistyped, or read from another run of the edge half
- the edge half was measured for another partner or on another edge host
- the declaration or the init flags differ between the two machines, so the edge was measured for another interface (or none)
- the edge half is older than a day, or one of the two machines' clocks is wrong

## What to do

One line per step or alternative:

```text
goatbuilder federate init --over-ssh <partner> --side edge --half-out <file> (on the edge driver, with the same declaration and init flags; it prints the confirm code)
sha256sum <file> (on both machines: the two must agree)
```
