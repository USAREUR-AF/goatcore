# GB-348: the copy did not finish

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-348` is printed by `goatbuilder`. The same text offline: `goat explain GB-348` or `goatbuilder explain GB-348`.

## What it means

After the re-seed dropped and created the node's subscription from the founder and asked for each table to be copied again, a table was still not copied (`spock.local_sync_status` other than `r`) or the subscription did not read `replicating` within the wait, or a slot on the node read `lost` during the copy. The node's tables may be partly copied; the founder's are untouched.

## Why it happens

- the copy is still running: a large table, or a slow link
- a table failed to copy (the node's Postgres log says why)
- the copy cost the founder its slot on the node (GB-347's case)

## What to do

One line per step or alternative:

```text
run the re-seed again; it starts at this step and waits again
on the node: SELECT * FROM spock.local_sync_status; and read its Postgres log
```
