# GB-353: a joining site already holds a shared secret that is not its founder's

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-353` is printed by `goatbuilder`. The same text offline: `goat explain GB-353` or `goatbuilder explain GB-353`.

## What it means

join-node's phase 3 takes a joining site's shared values from its founder and never overwrites one the joiner already holds. A joiner name holds a value (or a reference to one) whose SHA-256 differs from the founder's. A joiner with a fresh value looks healthy and cannot take part: NetBird cannot decrypt the replicated rows, Spock does not replicate, Kratos and Hydra cannot read the replicated identity data. The value was kept. The message names the variables, never a value or a digest.

## Why it happens

- the joiner's values were minted fresh, by hand or by newsite-secrets.sh, before this step existed
- the joiner's reference points at another goatnet's entry

## What to do

One line per step or alternative:

```text
decide which value is right; remove the joiner's own entry for that name from the store or the reference file, then resume with --from 3, and the step takes the founder's
for NetBird's datastore key: a joiner whose NetBird database already holds rows encrypted with its own key is rebuilt, not re-keyed
```
