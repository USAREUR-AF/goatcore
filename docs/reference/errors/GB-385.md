# GB-385: a component's play was not taken from its source repository

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-385` is printed by `goatbuilder`. The same text offline: `goat explain GB-385` or `goatbuilder explain GB-385`.

## What it means

The component's play is in another repository (`source:` in ops/pins/fleet-pins.yaml: repository, full commit, play). It is fetched on the operator's machine with that person's own git access before any host is touched. The message names the check that refused: `fetch` (not reachable with this access, or no such commit), `commit` (the copy kept here is not exactly that commit), `play` (the commit has no such file), `role` (it carries a role goatcore has), `declaration`, or `goatbuilder` when deploy-component.sh finds no goatbuilder that can fetch it. No host was touched.

## Why it happens

- this person's git access does not reach the repository
- the commit was never pushed, or was removed
- a file in the kept copy was changed

## What to do

One line per step or alternative:

```text
check access with git ls-remote, then run again
remove the kept copy the message names, and run again
name a commit that has the play, in a reviewed change of ops/pins/fleet-pins.yaml
```
