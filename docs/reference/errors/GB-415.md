# GB-415: first-bite's capture is not declared, or the dictionary it names is not in the release

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-415` is printed by `goatbuilder`. The same text offline: `goat explain GB-415` or `goatbuilder explain GB-415`.

## What it means

A machine of the type first-bite declares, in its host_vars, `first_bite_interface`, the interface first-bite captures on, and may name in `first_bite_dictionary` one of the dictionaries the release carries (the directory names under `dictionaries/` in its archive). There is no default. The machine declares no interface, or one that is not an interface name, or a dictionary that is not a directory name: ops/ansible/first-bite-deploy.yml stops before anything, and nothing was installed. Or the release has no dictionary of that name: the verified archive is already in place and its ledger row written, the play stops before first-bite's installer runs, a first-bite installed before keeps running as it was, and the play removes the component's `current` link, so verify reports the machine not converged.

## Why it happens

- the machine's host_vars have no `first_bite_interface`
- the interface or dictionary is not a plain name
- the release has no dictionary of that name

## What to do

One line per step or alternative:

```text
set `first_bite_interface: <interface>` in ops/ansible/host_vars/<machine>.yml
name a directory of the release archive's `dictionaries/`, or leave `first_bite_dictionary` unset
```
