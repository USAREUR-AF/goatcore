# GB-341: the IPsec rotation was not tested with this strongSwan

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-341` is printed by `goatbuilder`. The same text offline: `goat explain GB-341` or `goatbuilder explain GB-341`.

## What it means

An IPsec credential rotation (goat-peering-edge) relies on what strongSwan does when the switch loads the credentials: that swanctl --load-creds unloads the old leaf's key, and what --load-creds --clear and --list-certs show after it. That was measured on a real charon of the series in peering_edge_rotation_strongswan_tested (5.9 and 6.0 by default: 5.9.8 and 6.0.4). Before anything moves, the rotation reads the running charon's version (swanctl --version --daemon --raw). It reported a series not in the list, or no version at all, so nothing was moved.

## Why it happens

- the edge runs a strongSwan release of another series than the rotation was measured on
- charon is not running, or swanctl cannot reach it over vici

## What to do

One line per step or alternative:

```text
run the rotation on an edge whose charon is of a tested series
or run the rotation on this series in a lab first, then add the series (major.minor) to peering_edge_rotation_strongswan_tested in the deployment's group_vars
when no version was read, start charon (or fix the vici socket) and run the rotation again with the same id
```
