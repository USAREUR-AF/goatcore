# GB-439: the bootstrap NetBird token did not read back from the store as it was written

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-439` is printed by `goatbuilder`. The same text offline: `goat explain GB-439` or `goatbuilder explain GB-439`.

## What it means

Standup phase 11 stores the pending bootstrap token under the declared secrets posture and reads it back before switching it on (ADR 1274). The write was refused, the store kept a value it already held, or the value read back differs from the one written. The token was not switched on; it stays pending on the host, and a re-run resumes from it.

## Why it happens

- the store already holds a value under the token's name (a value store keeps an existing value)
- the 1Password item holds a different value, or the vault cannot be written
- the store file or the 1Password session is not writable from this machine

## What to do

One line per step or alternative:

```text
make the store writable (goatbuilder secrets doctor), then run phase 11 again
if the store holds an old value under the name, that is a rotation's case (ADR 1274), not a standup's
```
