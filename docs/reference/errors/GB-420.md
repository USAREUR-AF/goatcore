# GB-420: a target type's plays were not taken from its source repository

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-420` is printed by `goatbuilder`. The same text offline: `goat explain GB-420` or `goatbuilder explain GB-420`.

## What it means

The type's plays marked `from: source` are in another repository (`source:` in the type file: repository, and a full commit or a tag with the SSH key that signs it). A run of join-node or standup fetches that commit on the operator's machine with that person's own git access, into the state directory, before its first phase; no phase has run when it is refused there. The message names the check that refused: `fetch` (not reachable with this access, or no such commit or tag), `tag` (a lightweight tag, another tag under its name, or one made before the tag an earlier run took), `signer` (the tag carries no SSH signature, or not the declared key's), `commit` (the copy kept here is not exactly that commit), `play` (the commit has no such file), `role` (it carries a role goatcore has), `tree` (it carries variables, modules, plugins or collections of its own, a link, a submodule, or a file where a role of goatcore's reads one beside the playbook), or `declaration`. A tag is fetched and checked on every run. The same checks run again just before each of its plays; a refusal there stops that phase before the play. A plan fetches nothing.

## Why it happens

- this person's git access does not reach the repository
- the commit was never pushed, or was removed
- a file in the kept copy was changed

## What to do

One line per step or alternative:

```text
check access with git ls-remote, then run again
remove the kept copy the message names, and run again
name a commit that has the play, in a reviewed change of the type file
```
