# GB-032: the candidate record is open but the goatnet runs a different ref

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-032` is printed by `goatbuilder`. The same text offline: `goat explain GB-032` or `goatbuilder explain GB-032`.

## What it means

graduate.py's C6 check: a record for this component is still open while the goatnet now runs another ref — the record the preprod step superseded was never abandoned.

## Why it happens

- a release run on a checkout older than #2039, which abandons the superseded record in the preprod change
- a candidate re-cut while the previous record stayed open

## What to do

One line per step or alternative:

```text
re-run the same command from a current main: rc.sh and `goatbuilder release` abandon the superseded record in the preprod change (git pull --ff-only origin main first on an older checkout)
python3 ops/release/graduate.py status (what is open)
```
