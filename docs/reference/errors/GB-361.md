# GB-361: a joining site's data router and health publishers would name its Zenoh stack differently

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-361` is printed by `goatbuilder`. The same text offline: `goat explain GB-361` or `goatbuilder explain GB-361`.

## What it means

join-node deploys a joining site's data router (the goat-zenoh role) and then each health publisher the site declares. `zenoh_stack` names the router's directories, its container (`<stack>-router`) and its network (`<stack>_default`). The router's role defaults it to `<site_id>-zenoh`; a publisher's role reads it with a default of its own (`goat-zenoh`) or requires it. Ansible gives each role only its own defaults, so with no `zenoh_stack` in the site's group_vars the publishers would look for a router and network the site's router does not have. The message names each publisher and the value it would read. The plan was refused before any phase ran.

## Why it happens

- the site's group_vars do not set zenoh_stack, and a publisher role's default differs from the router role's

## What to do

One line per step or alternative:

```text
add the line the message prints, `zenoh_stack: <site_id>-zenoh`, to group_vars/<site>_hosts/, so every role reads one value
```
