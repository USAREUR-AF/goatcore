# GB-334: an observability leg failed

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-334` is printed by `goatbuilder`. The same text offline: `goat explain GB-334` or `goatbuilder explain GB-334`.

## What it means

A site that declares has_obs_host: true stands up its observability host in a leg beside the core phases, and that leg exited non-zero. The row prints the leg, its exit code and its log. The core phases before the one that needs the leg have run; that phase and the later ones did not.

## Why it happens

- the leg's own error, in its log (obs_scrape_targets unset is the usual one for the stack leg)

## What to do

One line per step or alternative:

```text
fix the cause, then: goatbuilder standup <environment> --site <site> --obs-only, and resume from the phase the row names
```
