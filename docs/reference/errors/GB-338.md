# GB-338: a federation verb faulted (the message names what)

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-338` is printed by `goatbuilder`. The same text offline: `goat explain GB-338` or `goatbuilder explain GB-338`.

## What it means

One of the federation verbs (goatbuilder federate init|lint|compose|diff|verify|apply, run on their own or inside a peering run) stopped on an error its library raised without a catalog code. The library's own refusals carry their codes (X-FED-001 to X-FED-007); this is what is left. goatbuilder prints the library's message unchanged and gives it this code. Nothing after the error ran.

## Why it happens

- the verb's report could not be written: the terminal or the pipe it was sent to closed before the verb finished (for example `goatbuilder federate lint ... | head -1`)
- a check of the library's own with no code of its own, such as its refusal to sign an acceptance result with the package signer

## What to do

One line per step or alternative:

```text
read the message: it names what failed; for a closed pipe, run the same command again with its whole output read, or with --json into a file
goatbuilder federate <verb> --help (the flags the verb takes)
```
