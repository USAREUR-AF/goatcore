# GB-338: a federation verb faulted (the message names what)

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-338` is printed by `goatbuilder`. The same text offline: `goat explain GB-338` or `goatbuilder explain GB-338`.

## What it means

One of the federation verbs (goatbuilder federate init|lint|compose|diff|verify|apply, run on their own or inside a peering run) stopped on an error its library raised without a catalog code. goatbuilder prints the library's message unchanged and gives it this code; a file the library could not read or write carries GB-254 instead. Nothing after the error ran.

## Why it happens

- a flag's value the verb could not use (a --now that is not a date, a --key that is not &lt;sovereign_id>=&lt;base64>, --confirm without --out)
- a refusal of the library's own (refusing to sign an acceptance result with the package signer, a party it could not resolve)
- the verb's report could not be written to the terminal

## What to do

One line per step or alternative:

```text
read the message: it names the flag, the party or the file; fix it and run the same command again
goatbuilder federate <verb> --help (the flags the verb takes)
```
