# GB-295: a cut-off site's access-rule cutover would have created or deleted a policy

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-295` is printed by `goatbuilder`. The same text offline: `goat explain GB-295` or `goatbuilder explain GB-295`.

## What it means

ops/ansible/netbird-acl-cutover.yml ran with cut_off=true, for a site cut off from the others. While cut off, a site may only update the access-rule policies it already has, by their ids: NetBird assigns a created policy's id, so two cut-off sites that each create the same rule leave two policies after the heal, and a delete at one site is undone or doubled by the other. This run would have created or deleted at least one policy (the message names each policy it would have created and each id it would have deleted), so it stopped before it wrote anything, updates included.

## Why it happens

- the access-rule matrix names a rule the site has no policy for yet
- reap_orphans=true, and the site holds a generated policy the matrix no longer names
- enforce with the Default policy action delete
- the teardown play, which only deletes

## What to do

One line per step or alternative:

```text
wait for the heal; the hub then runs ops/ansible/netbird-acl-cutover.yml without cut_off and makes the creates and deletes
when the message names only deletes: drop reap_orphans=true, or set the Default policy action to disable, and run again with cut_off=true
```
