# GB-301: a site does not hold what the machine class phone declares

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-301` is printed by `goatbuilder`. The same text offline: `goat explain GB-301` or `goatbuilder explain GB-301`.

## What it means

The machine class phone declares once, in ops/ansible/group_vars/class_phone.yml, what a phone node differs in: no LAN address, no public ingress, no disk encryption inside the VM, memory limits for 4 GB, no observability host. The config preflight (standup-config-preflight.py &lt;site>_hosts --class phone, phases 3, 7 and 12 of join-node) found the site at odds with it: its group_vars set one of the class's keys to another value or set a key the class rules out, its node is not under [class_phone] in inventory/mgmt-hosts.ini or has a LAN address there, or the class file is not in the checkout. The same code refuses --class phone at a site that does not declare goatnet_founder: false, before any phase.

## Why it happens

- the site's group_vars carry a value copied from a site of another class
- the node's line was not added under [class_phone] in ops/ansible/inventory/mgmt-hosts.ini
- the node's line in ops/ansible/inventory/mgmt-hosts.ini carries an ansible_host
- the site is a founder: a phone node joins a goatnet

## What to do

One line per step or alternative:

```text
python3 ops/scripts/standup-config-preflight.py <site>_hosts --class phone (each [class phone] line names the key or the inventory line)
remove the key the line names from ops/ansible/group_vars/<site>_hosts/
list the node under [class_phone] in ops/ansible/inventory/mgmt-hosts.ini, as the name alone
```
