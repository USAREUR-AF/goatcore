# X-OP-002: an op:// reference is malformed

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `X-OP-002` is an error of `op` that goat and goatbuilder carry and interpret. The same text offline: `goat explain X-OP-002` or `goatbuilder explain X-OP-002`.

## What it means

op run validates every op:// value in the environment and refuses the whole run when one has fewer than three parts (vault/item/field). The variable is often one from your shell profile, not the refs file.

## Why it happens

- a variable in your shell holds a two-part reference (op://Vault/Item)

## What to do

One line per step or alternative:

```text
env | grep 'op://' (find the variable)
env -u <THAT_VAR> op run --env-file=… -- <command>
or complete it to op://<vault>/<item>/<field>
```
