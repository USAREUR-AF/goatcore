# GB-309: the retire step finds no confirmed rotation to retire

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-309` is printed by `goatbuilder`. The same text offline: `goat explain GB-309` or `goatbuilder explain GB-309`.

## What it means

The retire step of an IPsec credential rotation (goat-peering-edge, peering_edge_rotation_retire) removes the set-aside key in .previous-&lt;id>/ on the edge, and nothing else: it never moves the live pair, the staged pair or our CA. It removes the key only once the new leaf is live: the live pair is not the set-aside one, the live key is the live certificate's, and an IKE SA established since the old pair was set aside has an installed CHILD SA (the SA that was up before authenticated the old leaf). This edge has no .previous-&lt;id>/ for the id given, or the rotation is not confirmed live, so nothing was moved or removed.

## Why it happens

- the id is mistyped, or names a rotation of another edge
- the rotation stopped before its switch, so the live pair is still the set-aside one
- the IKE SA is down, the only SA up was established before the rotation, or the live key is not the live certificate's

## What to do

One line per step or alternative:

```text
check the id the rotation printed (ls /etc/swanctl/.previous-*)
finish the rotation by running it again with the same id, confirm the link on both sides, then retire
```
