# GB-392: the secret store does not answer without a person

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-392` is printed by `goatbuilder`. The same text offline: `goat explain GB-392` or `goatbuilder explain GB-392`.

## What it means

A stand-up or a join-node reads and writes the secret store during the run (the site's secrets early, the service tokens later). Before it touches a host it asks the store for one read, bounded, with no terminal. The 1Password CLI did not answer in time, or refused: it is waiting for its prompt to be approved in the desktop app on this machine, the app is locked, or no session is signed in. An unattended run would have stopped at the first store call, minutes or an hour in, with nothing printed.

## Why it happens

- the 1Password desktop app is locked, or its authorization for this terminal has lapsed
- no session: op is not signed in to the declared account
- the approval prompt is on a screen nobody is at

## What to do

One line per step or alternative:

```text
unlock the 1Password app on this machine and approve the prompt, then re-run
eval $(op signin) (a CLI session), then re-run
GOAT_STORE_ANSWER_SECONDS=<n> sets how long the one read may take (default 30)
```
