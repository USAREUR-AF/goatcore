# GB-333: an image pull failed

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-333` is printed by `goatbuilder`. The same text offline: `goat explain GB-333` or `goatbuilder explain GB-333`.

## What it means

goatbuilder standup pulls the pinned images beside phases 3 and 4, and the pull exited non-zero. The row prints its exit code and its log, which names each image that could not be pulled. The phase that first runs those images, and every phase after it, did not run.

## Why it happens

- a private package and no GHCR_READ_TOKEN on the laptop (phase 2 logs the box in with it)
- a pin that names an image the registry no longer has

## What to do

One line per step or alternative:

```text
set GHCR_READ_TOKEN, or pin an image the registry has in ops/pins/, then resume from the phase the row names
```
