# GB-072: goatbuilder cannot name the download surface to update from

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-072` is printed by `goatbuilder`. The same text offline: `goat explain GB-072` or `goatbuilder explain GB-072`.

## What it means

update (and the behind-version notice) reads the release a goatnet serves at get.&lt;site_id>.&lt;site_dns_zone>/goatbuilder/. It looks at GOATBUILDER_UPDATE_URL, then --site (named from the site's group_vars), then the surface the last successful update used. None of them named a surface that serves goatbuilder for this machine.

## Why it happens

- the first update on this machine was run without --site, and GOATBUILDER_UPDATE_URL is not set
- the site named with --site has no ops/ansible/group_vars/&lt;site>_hosts/ in the checkout goatbuilder was run in
- the site does not serve goatbuilder (goat_get_goatbuilder_enabled is not true in its group_vars)
- no goatbuilder release is built for this operating system and architecture

## What to do

One line per step or alternative:

```text
goatbuilder update --site <site> (a goatnet that serves goatbuilder)
run it from a goat checkout, or pass -C <checkout>
GOATBUILDER_UPDATE_URL=https://get.<site>.<zone>/goatbuilder goatbuilder update
```
