# GB-382: a pin names no digest

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-382` is printed by `goatbuilder`. The same text offline: `goat explain GB-382` or `goatbuilder explain GB-382`.

## What it means

A member group's pins.yml declares the component's ref with no @sha256: digest: the value as YAML reads it (a trailing comment is not part of it) must end in @sha256: and exactly 64 lowercase hex characters. A tag can be moved to another image, so deploy installs only a ref pinned by its digest (contract C1). goatbuilder deploy and deploy-component.sh refuse it before any host, whatever the fresh-source check said of the tree; a dry run reports it, prints the whole plan and exits 1. --verify-only deploys nothing and is not judged.

## Why it happens

- the digest was removed from group_vars/&lt;group>/pins.yml by hand
- the value in ops/pins/fleet-pins.yaml was written as a tag, and pins.yml was rendered from it

## What to do

One line per step or alternative:

```text
write the ref as <image>:<tag>@sha256:<digest> in ops/pins/fleet-pins.yaml, then: goatbuilder pins
re-render the pins instead of editing pins.yml
```
