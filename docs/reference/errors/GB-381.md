# GB-381: a release component's file is not fetched or does not verify

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-381` is printed by `goatbuilder`. The same text offline: `goat explain GB-381` or `goatbuilder explain GB-381`.

## What it means

A release component (fleet-pins `artifact_type: release`) is fetched and verified on the operator's machine before any host is touched: the release's checksums file must have the pin's SHA-256 digest; its keyless signature (`<checksums>.cosign-bundle` beside it) must verify for the component's `release.signer` at the pin's tag; and each architecture's file must be listed in the checksums file with the SHA-256 it has. The pin's repository must also be the repository of the signer's workflow. The message names the check that refused (`repository`, `pin`, `declaration`, `trust-root`, `fetch`, `digest`, `signature`, `arch`, `listed`, `store`, or `goatbuilder` when deploy-component.sh finds no goatbuilder that can verify). No host was touched. `verify` prints it when it could not fetch the release to compare a host's file with; it reads hosts and changes none.

## Why it happens

- the release was changed after it was pinned, or the pin's digest is wrong
- the release was signed by another workflow, repository or tag than the component declares
- the pin names another repository than the one whose workflow is release.signer
- the release has no file for this architecture, or its checksums file does not list it
- the release or its signature cannot be downloaded from here, and no earlier run kept it
- ops/scripts/deploy-component.sh found no goatbuilder, or one older than this check (GOATBUILDER_BIN names one)

## What to do

One line per step or alternative:

```text
on a machine with no internet, set GOATBUILDER_RELEASE_MIRROR to a directory of <owner>/<repository>/<tag>/<file>
check the pin: the digest is the checksums file's SHA-256, and the tag is the release's
check `release.signer`: the workflow that signs the release, https://github.com/<owner>/<repository>/.github/workflows/<file>.yml, with no ref
```
