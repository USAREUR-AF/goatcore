# GB-352: a joining site cannot take a shared secret from its founder

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-352` is printed by `goatbuilder`. The same text offline: `goat explain GB-352` or `goatbuilder explain GB-352`.

## What it means

join-node's phase 3 gives a joining site the values every site of the goatnet shares (the SPEC lines of newsite-secrets.sh marked cluster: NetBird's datastore key, the replicator, the relay secret, Ory's network id, the Kratos cipher, the Hydra system secret) by taking its founder's. Under a store of references the founder's name has no reference in .envrc.local.d/\*.refs; under a store of values it has no value; or, after the secrets injector ran, the founder's or the joiner's name was empty or still a reference. Nothing was written for the joiner's shared names. The message names the variables, never a value.

## Why it happens

- the founder's value was never stored under the declared secrets posture on this machine
- the store's tool is not signed in, so with-secrets could not resolve the reference
- join_founder_site in the joiner's group_vars names the wrong site

## What to do

One line per step or alternative:

```text
python3 ops/secrets/posture.py hint <FOUNDER>_<NAME> says where to store it
sign in to the declared store's tool, then resume: goatbuilder join-node <environment> --site <site> --node <node> --class core --address <address> --from 3
```
