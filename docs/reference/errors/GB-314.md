# GB-314: the node does not answer at join-node's phase 1

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-314` is printed by `goatbuilder`. The same text offline: `goat explain GB-314` or `goatbuilder explain GB-314`.

## What it means

join-node phase 1 checks the node answers before anything is done on it: over SSH at --address (one batch-mode connection with this machine's ssh, a 10 s connect timeout and no password prompt), or for a phone node over the Android debug bridge (adb get-state). A node whose SSH server refuses the login has answered: before phase 2 seeds this machine's key, a password-only node refuses every batch login. This node did not answer: the connection never reached its SSH server (no route, refused, timed out, a name that does not resolve, a changed host key), or no single phone answers over USB. Nothing was done on the node and no later phase ran.

## Why it happens

- --address is not the box's address on the site LAN, or the box is off or not yet on the network (on a Jetson, 192.168.55.1 is the USB device-mode bridge, reachable only over a direct USB-C cable)
- the box's host key changed since this machine last connected (ssh names it), or the address is a name this machine cannot resolve
- for a phone: it is not attached, USB debugging is not allowed for this machine, its screen is locked, or more than one device is attached without ANDROID_SERIAL

## What to do

One line per step or alternative:

```text
ssh <user>@<address> (reach the box on the site LAN, then pass its real LAN address as --address)
adb devices (for a phone: it lists the phone as device; set ANDROID_SERIAL when several are attached)
goatbuilder join-node <env> --site <site> --node <node> --class <class> --address <address> --from 1
```
