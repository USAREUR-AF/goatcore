# GB-413: an image step ran and failed, or its proof does not hold

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-413` is printed by `goatbuilder`. The same text offline: `goat explain GB-413` or `goatbuilder explain GB-413`.

## What it means

`goatbuilder image <model> --step <name>` ran the builder's script for the step and the script failed (its own words, above, say why), or it finished and the step's proof, read straight after, does not hold: the message names each row that does not. The machine is as the script left it; the builder's scripts are each re-runnable.

## Why it happens

- the script stopped on something it checks (its words above)
- the script finished and the machine is not yet in the state it set up (a reboot or an unlock still to come)

## What to do

One line per step or alternative:

```text
correct what the script or the row names, then run the step again
goatbuilder image <model> --step <name> --check --host <user@address> (reads the proof again, runs nothing)
```
