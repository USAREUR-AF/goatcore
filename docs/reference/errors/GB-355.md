# GB-355: a standup play limited to the founder selects no host of the site's group

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-355` is printed by `goatbuilder`. The same text offline: `goat explain GB-355` or `goatbuilder explain GB-355`.

## What it means

Seven standup plays run on the site's first management host alone (SPIRE, the LAN service surface, the LAN TLS routes, the dashboard, the portal, grant-keyd, the dead-man watcher), limited with -l 'mgmt-&lt;site>-01\*', the declared naming rule. Before the play, the same command checked the site's group, &lt;site>_hosts, in inventory/mgmt-hosts.ini and inventory/mgmt-hosts-mesh.ini, and no host there matches the limit. The play was refused before ansible ran: with another host matching the pattern, ansible prints "skipping: no hosts matched" and exits 0 having done nothing. Both avenues, goatbuilder standup and goat-standup.sh, run the check (ops/scripts/inventory-hosts.py --match --require).

## Why it happens

- the site's first management host is named otherwise than mgmt-&lt;site>-01 in the inventory
- the host is listed under another group than &lt;site>_hosts

## What to do

One line per step or alternative:

```text
python3 ops/scripts/inventory-hosts.py <site>_hosts (run in ops/ansible; lists the hosts of the group)
name the site's first management host mgmt-<site>-01 in <site>_hosts, in inventory/mgmt-hosts.ini (and mgmt-hosts-mesh.ini when it lists it), then resume: goatbuilder standup <environment> --site <site> --from <phase>
```
