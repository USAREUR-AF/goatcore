# GB-310: the package held for a partner cannot be read, so it cannot be recorded as confirmed

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-310` is printed by `goatbuilder`. The same text offline: `goat explain GB-310` or `goatbuilder explain GB-310`.

## What it means

A peering whose phase 5 was confirmed by a goatbuilder that did not record the partner's package (before ADR 1229) has its held package recorded as the confirmed one on its first run under this build, before any phase: journaled as a migration, not as a person's confirmation, so a package older than it is refused and compose checks it. The package held for &lt;partner> at &lt;work>/theirs.canonical.json could not be read, so nothing could be recorded, and the run stopped rather than going on unprotected. Nothing ran.

## Why it happens

- &lt;work>/theirs.canonical.json was removed or moved, or is not readable by this user

## What to do

One line per step or alternative:

```text
put the package confirmed with the partner back at <work>/theirs.canonical.json, then run the same command again
or confirm the keys and the package with the partner again: goatbuilder federate <partner> --from 5 --partner-key <key> --partner-ca-fingerprint <fp>
```
