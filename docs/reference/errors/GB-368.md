# GB-368: an environment value is still an unresolved secret reference

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-368` is printed by `goatbuilder`. The same text offline: `goat explain GB-368` or `goatbuilder explain GB-368`.

## What it means

ops/scripts/ansible-preflight.sh found a variable whose value still begins with op://, bao:// or bw:// after the secrets injector ran. A play renders the environment as it finds it, so the reference would become a container's literal password or cookie secret. The message names each variable, never its value. Nothing was run on any host.

## Why it happens

- the command was not run through ops/scripts/with-secrets, so nothing resolved the references
- an inherited GOAT_SECRETS_RESOLVED told the injector the environment was already resolved
- GOAT_SECRET_REF_PREFIX names one store's scheme while a reference of another scheme is in the environment

## What to do

One line per step or alternative:

```text
ops/scripts/with-secrets <this same command>
env -u <NAME> <this same command> (a variable this play does not need)
```
