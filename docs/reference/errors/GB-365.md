# GB-365: a pins file breaks the pins schema

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-365` is printed by `goatbuilder`. The same text offline: `goat explain GB-365` or `goatbuilder explain GB-365`.

## What it means

goatbuilder pins, and every verb that runs its check (release, preflight, the fast lane), reads ops/pins/fleet-pins.yaml, its sidecar ops/pins/lite-pins.yaml, ops/pins/parity-capabilities.yaml and the unmigrated-pins list ops/pins/unmigrated-pins.txt, and holds them, and each intent it renders, to the pins schema: the shape of each table, a multi-arch index digest on every image, one owner for each member and var, a reason on every deviation. One rule is broken, and the message names the file, the component or goatnet, and the rule. Nothing was rendered.

## Why it happens

- a table or component is not in the shape the schema gives it (a list where a mapping goes, a key the sidecar does not carry)
- an image is pinned by a mutable or bare tag, not an index digest
- a goatnet, member or var is declared twice, or names a host group that does not exist
- a deviation has no reason, or sets both absent: and value:
- a row of the unmigrated-pins list is not &lt;member_group>:&lt;var>
- a release pin names another repository than its release.signer, or a release file name holds a character other than A-Z a-z 0-9 . _ + -
