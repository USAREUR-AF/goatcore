# GB-430: this machine class declares no NetBird groups of its own, so join-node does not enrol it

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-430` is printed by `goatbuilder`. The same text offline: `goat explain GB-430` or `goatbuilder explain GB-430`.

## What it means

`join-node` mints a node's setup key with the groups the founder's own peer holds, which are the site's INFRA group: what a management host joins, a core node or a phone node (which converges as core). No other class may take them: a break-glass node reaches only INFRA and NETWORK on port 22 (ADR 1114), a network-jump host is kept out of INFRA (ADR 1131), and no record puts an observability host there. Until the class declares the groups its node joins, the run is refused at phase 1, before the node changes, and phase 10 refuses on its own. Nothing was changed.

## Why it happens

- join-node --class &lt;class> for a class other than core or phone, over a range that includes phase 10

## What to do

One line per step or alternative:

```text
join-node --class <class> --to 9 (the phases before enrolment)
enrol the node by hand with the groups its class should hold, then resume with --from 11
```
