# GB-215: the host firewall would close a port this host listens on

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-215` is printed by `goatbuilder`. The same text offline: `goat explain GB-215` or `goatbuilder explain GB-215`.

## What it means

Before loading, the host firewall baseline reads the sockets the host listens on (ss) and found one, on a non-loopback address, that no rule admits and that the deployment has not named as closed on purpose. Loading would cut that service without anyone deciding it. Nothing was applied.

## Why it happens

- the host runs another service beside the peering (a management server, a portal, an exporter)
- a port the deployment means to close is not listed in goat_host_firewall_closed_listeners

## What to do

One line per step or alternative:

```text
admit it: goat_host_firewall_override: {other-tcp: {ports: [<port>], reason: "<why>"}}
close it on purpose: goat_host_firewall_closed_listeners: ["tcp/<port>"] (or the process name)
```
