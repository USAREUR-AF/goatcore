# GB-416: first-bite's settings capture on another interface than the machine declares, or do not decode with the installed dictionary

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-416` is printed by `goatbuilder`. The same text offline: `goat explain GB-416` or `goatbuilder explain GB-416`.

## What it means

first-bite's installer keeps a settings file it finds (/etc/first-bite/first-bite.env), so a machine whose declared `first_bite_interface` changed still captures on the interface that file names, and a machine first installed with no dictionary has no `BITE_DICT_PATH` when one is declared later. ops/ansible/first-bite-deploy.yml reads the file after the installer ran and stops when it names another interface, or when a dictionary is declared and the file does not point at the installed one. The play removed the component's `current` link, so verify reports the machine not converged.

## Why it happens

- the machine's `first_bite_interface` changed after first-bite was installed
- the settings file was edited by hand
- the machine declared a dictionary after first-bite was installed without one

## What to do

One line per step or alternative:

```text
set `FIRST_BITE_INTERFACE=<interface>` in /etc/first-bite/first-bite.env, then deploy again
or declare the interface the file names
set `BITE_DICT_PATH=/etc/first-bite/dictionary` in it when a dictionary is declared
```
