# GB-380: a network tap's mode is not declared, or its declaration is not valid

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-380` is printed by `goatbuilder`. The same text offline: `goat explain GB-380` or `goatbuilder explain GB-380`.

## What it means

A machine of a type that declares `tap` (the network tap) states in its host_vars how it sits on the link it records: `tap:` with `mode` (listen, which fails open, or inline, which fails closed: the link is down whenever the machine is), `source` when listening (copper-tap, bypass-relay or mirror-port), `ports` and `management`. There is no default. The machine declares none, or the message names what in its declaration is wrong and the file it is in. Nothing ran.

## Why it happens

- the machine's host_vars have no `tap:`
- a key is missing, unknown or templated, or the number of ports does not fit the mode and source
- the management interface is also listed as a port

## What to do

One line per step or alternative:

```text
write `tap:` in ops/ansible/host_vars/<machine>.yml, as ops/goatbuilder/targets/README.md shows
correct the key the message names
```
