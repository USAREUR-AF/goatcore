# GB-389: a client is connected to a database the rebuild truncates

Generated from `ops/errors/catalog.yaml` by `ops/ci/check-error-catalog.py --write`; do not edit here. `GB-389` is printed by `goatbuilder`. The same text offline: `goat explain GB-389` or `goatbuilder explain GB-389`.

## What it means

The rebuild's export and reseed steps read `pg_stat_activity` on the node, and a client other than the rebuild itself is connected to a database whose tables the rebuild truncates and copies again. A write that client makes after the export is in no file, and the truncate would lose it. The line names each database, role, application and client address. Nothing was changed.

## Why it happens

- the site's services that write to these databases (the mesh management service, the identity services) are still running
- an exporter or an operator's psql session is connected

## What to do

One line per step or alternative:

```text
stop the site's services that use these databases, as docs/operations/spock-site-rebuild.md says, then run the rebuild again; it starts at this step
on the node: SELECT datname, usename, application_name, client_addr FROM pg_stat_activity WHERE backend_type = 'client backend';
```
