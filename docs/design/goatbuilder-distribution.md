## What this is

`goatbuilder` is hosted exactly the way `goat` is — one signed build, served from two homes — plus one rule the builder needs that the runtime client does not: the **first** copy of the tool that builds an environment cannot come from that environment. Every copy after the first can.

| Home | Who it serves | What it is |
|---|---|---|
| **Public** — GitHub Releases on the open-source repository, and the public docs site, each linking to the other | anyone bootstrapping a goatnet; the external teams who run their own repos (ADR 1197) | the release artifacts and their signatures, the docs rendered from this repository |
| **Private** — `get.<site>.<zone>` inside each ZAGROS goatnet (`zagros-dev`, `zagros`, `zagros-prod`), with `docs.<site>.<zone>` beside it | operators already inside a goatnet; air-gapped and islanded sites | the **same** signed artifacts, served mesh-only, never a fork |

The two homes carry one build with one signature. The private copy exists for reach (an operator on the mesh, a site cut off from the internet), never for a different version.

## The catch-22, and how it resolves

The tool that stands a goatnet up is hosted inside goatnets. That is only circular for the first copy:

1. **Bootstrap** — the first goatnet of an organization, or a founder site with nothing to reach, gets `goatbuilder` from the public release or from an operator's laptop that already has it. This is the same seat that holds the bootstrap credentials ([goatnet-standup.md](../operations/goatnet-standup.md) phase 1) and it is the only time the binary arrives from outside.
2. **Every later copy comes from inside.** Once a goatnet serves `get.<site>`, operators download from it; a joiner site's standup pulls the binary from its founder's surface; and under the pull model the binary is one more **signed artifact on the registry chain** — an islanded site gets it from its nearest store, exactly as it gets a release (contract C2: trust is in the signed content, not in where it was fetched).
3. **The signature is the same in both homes**, so a copy from `get.zagros` and a copy from GitHub verify identically against the organization's key. A partner or an air-gapped site can host the surface without being able to alter a byte.

So the rule is: *a goatnet never needs the internet to hand its operators the builder, and the builder never needs a goatnet to exist before the first goatnet does.*

## The release

Applies goat-cli's release path to a second binary, with no new machinery:

| Step | Mechanism |
|---|---|
| **Tag** | `goatbuilder/vX.Y.Z` on `main`, nominated by a repository admin — the rule `rc-validate.yml` already enforces for every candidate ([ADR 1173](../adr/1173-release-candidate-tags-trigger-affected-flow-validation.md)) |
| **Build** | `goatbuilder-release.yml`, the shape of `goat-cli-release.yml`: Linux `x86_64` + `aarch64` and macOS, static where the target allows, `cargo test` and `clippy -D warnings` gating the build |
| **Sign** | `SHA256SUMS` over every artifact, signed keyless with cosign (`SHA256SUMS.cosign-bundle`): a short-lived Fulcio certificate for the release run's GitHub Actions identity, and the signature recorded in Rekor. A verifier of a release (`goatbuilder update`, in process, `crates/goatbuilder/src/update/signature.rs`; anyone by hand) runs six checks, all of these, each of which must pass: (1) the certificate chains to a Fulcio CA of the trusted root, carries the codeSigning extended key usage, is not a CA, has no critical extension the verifier does not handle, and is valid at the signature's `integratedTime`; (2) an SCT embedded in the certificate verifies under a trusted certificate-transparency log that was valid at the SCT's own time; (3) Rekor's SignedEntryTimestamp verifies under a trusted transparency-log key; (4) the hashedrekord entry names this `SHA256SUMS`'s sha256, this signature and this certificate; (5) the signature over `SHA256SUMS` verifies with the certificate's public key; (6) the certificate names the release's own identity: the issuer is GitHub Actions (`https://token.actions.githubusercontent.com`); the source repository is the release's repository; the source ref is exactly `refs/tags/goatbuilder/v<version>` for the version served; and the Build Config URI is `<repository>/.github/workflows/goatbuilder-release.yml@refs/tags/goatbuilder/v<version>`. The certificate's SAN alone is not enough: it names the shared `_release-binary.yml`, which every release workflow in the repository calls (goat's as well as goatbuilder's), so a match on the SAN or on the repository accepts any of them. These are gate row E4's checks, for a surface that serves releases |
| **Update gate** | before the release is published, job `update-gate` in `_release-binary.yml` (on for goatbuilder, `update_gate: true`) runs the earlier releases' own `goatbuilder update` against the candidate it has just built and signed, on a local stand-in for `get.<site>/goatbuilder/` (`ops/ci/goatbuilder-update-gate.py`): the last release of each 0.x minor from the declared floor, and the last of each later major (`ops/ci/goatbuilder-update-gate.yaml`). Each runs from an empty directory, so its own compiled-in trust decides, with cosign on PATH, and passes only when it reports a signature it verified for this repository's release workflow, installs the candidate, and then reports the candidate's version. The same candidate served with the previous release's `SHA256SUMS.cosign-bundle` must be refused by every one. Any other result blocks the publish. A release that cannot update and cannot be fixed in place is declared with the code it refuses with and the fix its catalog entry gives (`refuses`), or, if it is not published in this repository, by the sha256 of its binary (`measured_elsewhere`) |
| **macOS** | the code-signing step goat-cli needed to stop the launch hang, or the binary does not run for a Mac operator |
| **Publish** | a GitHub Release on the source repository; the private `get.<site>` surfaces pull the same artifacts on their bump path |
| **Promote** | `goatbuilder` is a component like any other: a release candidate travels dev → preprod → prod on the ladder — through its own `release` verb once that verb is ported, through `rc.sh` until then |

The binary ships the schema it validates against, so a release of `goatbuilder` is a release of the schema version it enforces; the config's `schema:` field names which one a repository expects.

## Inside the goatnet — `get.<site>` and `docs.<site>`

`goatbuilder` becomes a second artifact on the surface [`goat-cli-mesh-download.md`](goat-cli-mesh-download.md) already defines, not a second surface:

- `https://get.<site>.<zone>/goatbuilder/<version>/<platform>/goatbuilder`, with the aggregate `SHA256SUMS` and the landing page's install one-liner extended with the builder; mesh-only by the shared Traefik allowlist; LE certificate on first request.
- **Staleness and self-update**: `goatbuilder update` replaces the binary with the release `get.<site>` serves, the way `goat update` does, on the same core (`crates/goat-selfupdate`). The surface is `GOATBUILDER_UPDATE_URL`, else `--site <site>` named from the site's group_vars (`site_id`, `site_dns_zone`, `goat_get_goatbuilder_enabled`, as the goat-get role renders the hostname), else the surface the last update used (`~/.goatbuilder/update-check.json`). Before the installed binary is touched it checks the asset against its `.sha256`, that digest against `SHA256SUMS`, and the keyless signature over `SHA256SUMS` (`SHA256SUMS.cosign-bundle`), verified in the binary with no cosign (`crates/goatbuilder/src/update/signature.rs`). That check is offline from the bundle. The certificate must chain to a Fulcio CA of the Sigstore trusted root valid at the entry's time, and Rekor's signed entry timestamp must verify over the canonical payload. The leaf's embedded SCT must verify under a Certificate Transparency log of the trusted root, over its precertificate (RFC 6962), as cosign's verify-blob checks by default. The leaf must not be a CA, and must mark no extension critical that the verifier does not handle. The entry must name this file, signature and certificate. The identity must be a trusted release signer's: one of the signers compiled into the binary (`RELEASE_SIGNERS` in `crates/goatbuilder/src/update.rs`), or the repository `goatbuilder.yaml` names (`repo.release_source`, else `repo.source`), which is trusted beside them, never instead of them; the binary's own build provenance is never a signer, and a signer change overlaps old and new for one release (ADR 1252). A refusal names each signer checked and why it refused. For that signer the identity is the GitHub OIDC issuer, that source repository, the served version's `goatbuilder/v<version>` tag as the source ref, `goatbuilder-release.yml` at that tag as the Build Config URI, and the signer's `_release-binary.yml` at that tag as the certificate's SAN. goat's release runs the same reusable workflow, so the SAN alone does not identify a goatbuilder release; it is matched, with Fulcio's legacy GitHub workflow repository, ref and name extensions whenever the certificate carries them (`goatbuilder-release` as the name), so that the binary and a cosign reinstall line pinned with `--certificate-identity` and `--certificate-github-workflow-repository`, `-ref` and `-name` trust one definition; ADR 1252 lists each field. The trusted root is the public Sigstore instance's, embedded; `GOATBUILDER_UPDATE_TRUSTED_ROOT` names a trusted_root.json whose keys are trusted beside it, so an islanded site takes a Sigstore key rotation without a new binary. A signature that does not verify, or is not served, refuses the update (GB-261); there is no unchecked path. Status: built, unit and integration tests only; WIP — gate: an update from a published release served by a real get.<site> surface. The binary download is bounded by a 30-second stall, not a total (`GOATBUILDER_UPDATE_STALL_SECS`). `--check` reads only and exits 3 when behind. Every other verb prints one behind-version line on a terminal at most once a day (off with `GOATBUILDER_NO_VERSION_CHECK`), and `goatbuilder doctor` adds a `goatbuilder version` row, failing while the binary is behind — the builder is the one tool whose staleness can silently reintroduce a fixed defect. Errors GB-072 (no surface), GB-073 (surface unreadable or stalled), GB-074 (checksum disagrees), GB-075 (cannot replace the binary), GB-078 (no release signer is known; no longer raised, since the declared signers are always known), GB-261 (the signature does not verify, or is not served).
- **Docs**: chapters on `docs.<site>.<zone>` composed from the canonical files by include, never forked — `goatbuilder.md` (overview and contract), the one-page deploy guide, `goatbuilder-conformance.md`, this document, the error and exit-code reference generated from the binary (`-o json` is the stable machine contract), and a *Getting started* chapter that is `goatbuilder tutor` on `--mock` written down.
- **Air-gapped sites**: the artifact is carried by the same chain as the images (the pull paper's release bundle; octo-pod's air-gap bundle is the appliance-side precedent), so a site with no path out still serves `get.<site>` from what it last pulled.

The DNS record and the Traefik route are the per-site service records the mesh-download role already renders; adding the builder is one more artifact in that role, not a new role.

## After open-source

When the core goes public (ADR 1197), the public home becomes the open-source repository's GitHub Releases and its docs site, and the two homes are **mutually linked**: the public docs name `get.<site>` as the in-goatnet path and the goatnet landing page names the public release as the bootstrap path. The private goatnets keep serving the same signed artifacts for reach; they never become a different build. An external team's goatnet runs the same binary with its own config.

## Documentation standard

The builder's documentation is held to goat-cli's: a design of record ([`goatbuilder.md`](goatbuilder.md)); a one-page operator guide (the deploy guide, which replaces its script-era predecessor as each verb lands); the contract as tests ([`goatbuilder-conformance.md`](goatbuilder-conformance.md)); `--help` that is complete enough to work from, `-o json` as the reference a program reads; `tutor` as the hands-on path on the mock fixture; and the hosted book above, always matching the binary an operator just downloaded. A verb is not done until its runbook step is deleted and its chapter is written.

## Build order

1. `goatbuilder-release.yml` on `goatbuilder/v*`, signed, with the macOS step — the first public home. **Built**; released as v0.1.0 and v0.2.0.
2. The builder as a second artifact in the mesh-download role; `get.zagros-dev` first, then `zagros` and `zagros-prod` on the ladder — **built**, off by default per goatnet; `update` and the staleness check in `doctor` — **built**.
3. The docs chapters on `docs.<site>`, composed by include — **built**; the CLAUDE.md pointer landed with this step.
4. The pull-chain carriage of the artifact, when the pull converger lands for the first class.
