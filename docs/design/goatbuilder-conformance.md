## What this is

The deploy contract in [`goatbuilder.md`](goatbuilder.md) is a set of guarantees a verb makes. This document turns each guarantee into a test with a fixture, an action and an assertion, so that "conforms to the contract" is a thing a build either passes or fails. The suite is the specification: a converger, a transport or an environment kind is admitted by passing it, and a config the suite passes behaves to contract on any repository.

One fixture serves three needs, by design: the conformance suite, golden tests in CI, and `goatbuilder tutor` — the same keystone that let `goat-cli` test its whole onboarding flow with zero infrastructure (`goat-cli-e2e-testing.md`). It is reached from the binary as `--mock <fixture>`.

## The first conformance test is already running

The config schema gate is built and gates every pull request that touches it:

| Piece | Path | What it holds |
|---|---|---|
| the schema | `ops/goatbuilder/schema/goatbuilder-v1.schema.json` | Draft-07, fail-closed (`additionalProperties: false` throughout); the gate vocabulary is the release ladder's own |
| this repository's config | `ops/goatbuilder/goatbuilder.yaml` | **generated** from `ops/pins/fleet-pins.yaml` + `ops/release/ladder.yaml` by `gen-config.py` — never hand-edited; one fact, one home |
| the validator | `ops/goatbuilder/validate.py` | the schema plus the cross-field rules JSON Schema cannot express; exit 0 / 1 / 2 like `ops/operators/validate.py` |
| the refusals, locked | `ops/goatbuilder/test_schema.py` | 17 tests: every shape the schema must refuse, and that the real 30-component config fits |
| the CI gate | `.github/workflows/goatbuilder-schema.yml` | drift (`gen-config.py --check`), validity, and the refusal tests, on every PR touching the sources |

That gate is contract clause **C3** at the config layer — the tool never acts on a declaration it cannot read exactly. The clause tests below carry C3 to the declaration itself.

## The fixture: a mock topology and a scripted converger

`--mock <fixture>` loads a directory, not a host:

```
fixture/
  goatbuilder.yaml        # a topology that validates against the schema (any shape)
  declared/               # the declaration files the config's declared_in paths point at
  records/<env>/<machine>.jsonl   # each machine's record stream, in ledger form
  converger.yaml          # how the scripted converger behaves, per machine
```

The scripted converger implements the three calls of the converger interface against the files above instead of a host:

| Call | Mock behaviour |
|---|---|
| `publish(env, site, class, component, ref)` | appends the publication to `declared/` (push: the pin; pull: a signed index with the next serial) |
| `observe(env, site, class, component, deadline)` | for each machine, follows `converger.yaml`: *converge now*, *converge after N ticks* (pending until then), *never* (stays pending), *unreadable* (unknown), or *apply on trigger* — the machine converges only when an operator-side apply is invoked, which is the self-converging appliance shape `octo-pod` has today |
| `read_record(machine, component)` | the last line of that machine's `records/` file, or *unreadable* when `converger.yaml` says so |

Every behaviour the contract must survive — a stale checkout, a replayed declaration, a machine that never converges, a record that cannot be read — is one line in `converger.yaml`, so each clause test is a small, readable fixture rather than a special environment.

## The clause tests

Each row is a test: the fixture state, the verb run, and what must be true afterwards. Exit codes follow the machine contract (C10): `0` done, `1` refused with a named reason, `2` usage or dependency, `3` not converged (pending or unknown remain), and every refusal names its recovery command on stderr and in `-o json`.

| Clause | Fixture | Action | Assertion |
|---|---|---|---|
| **C1** immutable ref | the working tree carries a *different* pin than `declared/` | `deploy --env dev` | the record names `declared/`'s digest, never the tree's; a mutable tag in `declared/` is refused, exit 1 |
| **C2** signed and ordered | `declared/` holds serial 41 after serial 42 was accepted; and a tampered index | `deploy` | both refused, exit 1, naming "older than last accepted" / "signature"; a *new* serial 43 at an old digest is accepted (that is a revert) |
| **C3** fresh source | the local copy of `declared/` is behind the fixture's source of record | `deploy` | fast-forwarded and applied, or refused with the fast-forward command — never applied from the stale copy; with `--frozen`, always refused |
| **C4** attributed | — | `release --ack "A Person"` | the declaration and the record both carry the actor |
| **C5** idempotent, resumable | a converged environment; then a converger that fails at machine 3 of 5 | `deploy` twice; then `deploy` after the failure | the second run reports zero change; the resumed run starts at machine 3, exit 0 when all converge |
| **C6** least privilege | `converger.yaml` records which transports were opened | `deploy --env dev` | only `dev`'s transport opened; none for other environments; under `pull-agent`, none at all |
| **C7** verified-done per machine | one machine *never*, one *unreadable*, three *converge now* | `deploy`; `status -o json` | exit 3; `status` lists 3 converged, 1 pending, 1 unknown; neither pending nor unknown is ever summed into "done" |
| **C8** inspectable | drift: a record ahead of or behind the declaration | `diff`, `history`, `status` | correct declared-vs-actual, no file in `declared/` or `records/` modified (checked by hash before and after) |
| **C9** reversible | a converged environment at digest B, previously A | `rollback --env dev` | a new declaration at A travels the same path; the record names A under a newer ordering; works with the converger set to *never* for an islanded machine (the revert is declared and pending, not failed) |
| **C10** machine contract | — | every verb with `-o json` and with `-o table`; `--yes`; a TTY-less run | JSON validates against the output schema and carries its version; a mutation without `--yes` and without a TTY is refused, exit 1 |
| schema | a config with an unknown field, a bad converger, a soak with no `min_days`, a rung with no environment, an undeclared environment | `validate` | refused, exit 1, each naming the field — **built**, `test_schema.py` |

## The parity gate

Both avenues stay live (ADR 1201: the scripts documented, the CLI supported), so a verb ships only when it produces the same outcome as the script beside it, and the gate keeps them identical from then on. The parity test runs both against the same fixture and asserts identical `declared/` and `records/` afterwards, the way `registry-parity` already gates image refs:

| Verb | Script it must match | Compared |
|---|---|---|
| `release` | `ops/scripts/rc.sh` | the pin merged per rung; the ledger digest per host; the candidate record |
| `deploy` | `ops/scripts/deploy-component.sh` | the ledger row per host (digest, action) and the converged / not-converged verdict |
| `rollback` | `ops/scripts/rollback.sh` | the prior digest restored; the rollback ledger row |
| `promote` | `ops/release/graduate.py`, `ops/scripts/fastlane.sh` | the pin per rung; the record graduated |
| `pins` | `ops/pins/generate-pins.py` | byte-identical generated pins and intents |

Parity holds and keeps holding: the script is never deleted (ADR 1201). A gate that fails on either side is fixed on both sides in the same change; the script never depends on the binary.

## Rehearsing a standup on the fixture

The fixture is also where a fresh environment's standup is rehearsed before any hardware is touched: a `goatbuilder.yaml` describing the site to be built, `records/` empty, and a converger that converges every machine. `standup --mock` declares every component for every class, converges them in the doctrine's phase order, and verifies every record — in milliseconds on the fixture (`ops/goatbuilder/fixtures/standup/`, built 2026-10-28) — before the same config is run against real hardware. The time the real run takes, declared to verified, is the number the one-hour-goatnet target is measured against (`goatbuilder.md` §"Standing up a goatnet in an hour").
